## 1. 原始需求映射

| 原始需求 | 实现 | 说明 |
|---|---|---|
| 登录：账号、密码、图形验证码 | `/login` + `GET /api/v1/auth/captcha` + `POST /auth/login` | 验证码 5 分钟有效、一次性 |
| 注册：账号、密码、确认密码、验证码 | `/register` + `POST /auth/register` | 两次密码一致；注册成功自动登录 |
| 对话：选择一个或多个知识库 | `/chat` 多选知识库 | 至少选 1 个；默认全选 |
| 检索所选知识库上下文 | Milvus 按 `kb_id in [...]` 过滤 | 稠密 / 混合检索 |
| 精心中文 Prompt | `services/prompt.py` | 只依据资料、带引用、资料不足时拒答 |
| 新建/命名/删除会话 | 会话侧栏 + API | 会话按用户隔离 |
| 选择大模型 | **不做**，固定 `deepseek-flash` | 按用户最新要求 |
| 推理参数 | 温度、Top P、max_tokens、历史轮数 | 历史默认 5，范围 0–20 |
| 知识库解析：上传 PDF/PPT/Markdown/图片 | 管理员知识库详情页上传 | `.pptx`、`.pdf`、`.md`、图片、`.docx` |
| 配置切块大小、重叠、稠密/混合 | 上传弹窗 + 知识库设置 | 文档级切块快照；知识库级检索模式 |
| 知识库预览：文档块详情 | `/admin/documents/:id` | 分页、搜索、编辑、删除 |
| 知识库管理：多知识库、多文档 | `/admin/knowledge` | 管理员专属 |
| 后端 FastAPI | `src/enterprise_rag` | 分层：api/services/ingest/infra |
| 用户数据 MySQL | SQLAlchemy + MySQL 8.0 | 表结构见 02 |
| 文档分块、向量化入 Milvus | bge-m3 + Milvus 2.6 | 稠密 + BM25 |
| 通义千问 → DeepSeek | 固定 `deepseek-flash` | 按用户最新要求 |
| 流式输出 + 历史对话 | SSE + 历史轮数 | 默认 5 |
| 重要信息放配置文件 | `.env` + `pydantic-settings` | 不提交真实 Key |
| 测试用例 | pytest / Vitest / Playwright | 见 04 |
| 中文页面与提示词 | 全站中文 + 中文 System Prompt | — |
| 年轻化、动态、简约大气 | 渐变光斑、玻璃卡片、微动效 | 见 06 前端设计 |

## 2. 角色与权限

| 能力 | 普通用户 `user` | 管理员 `admin` |
|---|---:|---:|
| 注册 / 登录 | ✅ | ✅ |
| 查看可用知识库 | ✅ | ✅ |
| 选择知识库对话 | ✅ | ✅ |
| 会话新建/改名/删除 | ✅（仅自己的） | ✅（仅自己的） |
| 创建/编辑/删除知识库 | ❌ | ✅ |
| 上传/解析/删除文档 | ❌ | ✅ |
| 预览/编辑/删除文档块 | ❌ | ✅ |
| 浏览只读 Wiki | ❌ | ✅ |

- 管理员通过 `.env` 的 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 首次启动时种子创建。
- 注册用户固定为 `user`，没有管理员注册入口。
- 会话按 `user_id` 隔离，管理员也不能查看他人会话。

## 3. 范围

### 3.1 本期包含

- 单实例部署；MySQL + Milvus 通过 docker compose 启动。
- 本地 bge-m3 编码；DeepSeek 云端流式生成。
- 文档解析：PDF、PPTX、Markdown、PNG/JPG/WEBP、DOCX。
- 扫描 PDF / 图片走 RapidOCR。
- 只读 Wiki：由文档块实时拼装，不改检索、不新增表。
- 日志、请求 ID、健康检查、OpenAPI。

### 3.2 本期不包含

- 密码修改/找回、OAuth、邮箱验证。
- 用户管理后台、多租户、知识库共享/协作。
- 可编辑 Wiki、外部 Wiki（Confluence/MediaWiki/Notion）接入。
- PolicyPoint + 图谱编译式 Wiki。
- bge-m3 sparse / ColBERT 输出；v1 混合检索使用 Milvus BM25。
- Reranker、查询改写、引用逐字校验。
- 旧格式 `.ppt` / `.doc`；请转 `.pptx` / `.docx`。
- API/前端容器化；compose 只负责 MySQL + Milvus 基础设施。

## 4. 验收口径

1. 登录/注册/验证码正常，普通用户无法访问管理端接口。
2. 管理员能创建多个知识库，每个知识库上传多个文档并解析到 Milvus。
3. 文档块可预览、编辑、删除；编辑后 MySQL 与 Milvus 同步更新。
4. 普通用户可选 1 个或多个知识库提问，SSE 流式返回，答案带来源引用。
5. 会话可新建/改名/删除，历史轮数、温度、Top P、max_tokens 可配置。
6. 知识库为空或检索不到资料时，明确拒答，不编造。
7. 删除文档/知识库时清理 MySQL、Milvus 与上传文件。
8. 只读 Wiki 能打开、搜索、下载，内容与当前文档块一致。
9. 控制台与 `logs/app.log` 均有日志。
10. pytest、Vitest、Playwright 全部通过。
