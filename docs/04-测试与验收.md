## 3. 覆盖场景

### 认证

- 验证码获取、注册成功、重名 409、两次密码不一致 422、验证码错误 400。
- 登录成功/失败、JWT 失效、普通用户访问管理员接口 403。
- 测试环境 `debug_code` 仅用于自动化。

### 知识库与文档

- 管理员创建/查询/更新/删除知识库。
- 普通用户只能读列表，不能创建/上传/预览管理端。
- 上传 Markdown → 解析 → 切块 → 写入 Milvus。
- 同知识库重复文件 409。
- PDF/PPTX/Markdown 解析；图片 OCR 可选集成测试。
- 文档状态 `pending → ready`，失败记录 `error_message`。
- 删除文档/知识库清理 MySQL 与 Milvus。

### 文档块

- 分页、关键词搜索。
- 编辑内容 → MySQL 更新 + Milvus upsert。
- 删除块 → MySQL + Milvus 删除。
- Wiki 实时反映编辑结果。

### 检索与问答

- 稠密 / 混合检索；多知识库合并；RRF 去重取 Top K。
- 空知识库/无命中 → 固定中文拒答，不调用 LLM。
- SSE 事件顺序：`meta → ping → citations → delta… → done`。
- 历史轮数、温度、Top P、max_tokens 透传；请求体无 `model`。
- 会话按用户隔离；管理员不能读他人会话。
- 客户端中断 → assistant 消息标记 `aborted`。
- LLM/向量库异常 → SSE `error`，消息标记 `error`。

### 只读 Wiki

- 文档 Wiki 含 frontmatter、片段章节、来源文件。
- 知识库 Wiki 含文档索引、块数、状态。
- `?download=1` 返回 Markdown 附件。
- 不新增表、不调用 LLM、不影响检索。

## 4. 端到端（Playwright）

文件：`frontend/e2e/app.spec.ts`

流程：

1. 管理员登录。
2. 通过 UI 创建知识库。
3. 上传 `data/samples/policy_faq.md`，等待状态“已就绪”。
4. 打开文档预览，编辑第一个文档块并保存。
5. 打开 Wiki 视图，断言包含“西部计划”。
6. 退出并注册普通用户。
7. 提问“西部计划服务期一般是几年？”，断言：
   - 出现 user + assistant 两条消息；
   - 出现来源引用卡片；
   - 回答包含“根据现有知识库”。
8. 重命名会话。
9. 普通用户访问 `/admin/knowledge` 被重定向到 `/chat`。
10. 删除会话，消息清空。

E2E 环境：

- 独立 MySQL 库 `enterprise_rag_e2e`。
- 独立 Milvus 集合 `kb_chunks_e2e`。
- `EMBEDDING_PROVIDER=hash`、`LLM_PROVIDER=mock`（不消耗真实额度）。
- 真实 MySQL + Milvus 仍参与测试。
