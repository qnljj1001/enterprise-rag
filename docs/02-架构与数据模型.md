# 02 · 架构与数据模型

> 版本 v1.0｜日期：2026-10-20

---

## 1. 总体架构

```text
Vue 3 SPA（5174）
   │ Bearer JWT / SSE
   ▼
FastAPI（8001）
   ├── api/            薄路由：auth / knowledge-bases / documents / chunks / chat / wiki / system
   ├── services/       认证、验证码、知识库、入库、检索、问答、Prompt、Wiki
   ├── ingest/         PDF/PPTX/MD/图片/DOCX 解析、切块
   ├── infra/          MySQL、Milvus、bge-m3、DeepSeek、RapidOCR、文件存储
   └── ports.py        VectorStore / Embedder / LLM 协议
        │
        ├── MySQL：用户、验证码、知识库、文档、文档块、会话、消息
        ├── Milvus：bge-m3 稠密向量 + BM25 稀疏向量
        ├── bge-m3：本地 1024 维编码
        └── DeepSeek：deepseek-flash 流式生成
```

### 分层约定

| 层 | 职责 | 不做什么 |
|---|---|---|
| `api` | 参数校验、鉴权、调用服务、组装响应 | 不写业务逻辑 |
| `services` | 业务编排 | 不直接依赖 FastAPI |
| `ingest` | 解析与切块 | 不碰数据库 |
| `infra` | 外部系统实现 | 不写业务规则 |
| `ports.py` | 可替换协议 | 供测试注入 Fake |

## 2. 数据流

### 2.1 上传与入库

```text
管理员上传文件
  → 保存到 data/uploads/{kb_id}/...
  → documents.status = pending
  → 后台 worker 取任务
  → parse_file（PDF/PPTX/MD/图片/DOCX）
  → chunk_blocks（按段落/句子边界，保留页码/字符区间）
  → 写入 document_chunks（MySQL）
  → bge-m3 批量编码
  → 写入 Milvus（content + embedding + BM25 稀疏向量）
  → documents.status = ready, progress = 100
```

状态：`pending → parsing → chunking → embedding → indexing → ready`；失败为 `failed`，保留 `error_message` 供前端展示。

### 2.2 检索与问答

```text
用户提问
  → 校验会话归属、知识库、参数
  → 按知识库 retrieval_mode 分组
      ├── dense：bge-m3 查询向量 → Milvus COSINE
      └── hybrid：bge-m3 查询向量 + 原始文本 → Milvus BM25，RRF 融合
  → 跨组 RRF 合并、按 chunk_id 去重，取 Top K
  → 从 MySQL 补文件名/知识库名/页码
  → 组装中文 Prompt（系统规则 + 历史 + 参考资料 + 当前问题）
  → DeepSeek deepseek-flash 流式生成
  → SSE：meta → citations → delta… → done
  → 保存 user/assistant 消息、引用、参数、usage
```

检索为空时不调用 LLM，直接返回固定中文拒答。

### 2.3 只读 Wiki

```text
GET /api/v1/admin/documents/{id}/wiki
  → 从 MySQL 读取文档与文档块
  → 拼接 frontmatter + 标题 + 每个块的小节
  → 返回 Markdown（或下载 text/markdown）
```

- 不新增表、不改检索、不调用 LLM。
- 编辑文档块后，Wiki 立即反映（每次实时组装）。
- 知识库 Wiki 是文档索引（文件名、块数、状态）。

## 3. MySQL 模型

| 表 | 关键字段 | 说明 |
|---|---|---|
| `users` | `id`, `username` 唯一, `password_hash`, `role`, `is_active`, `last_login_at` | Argon2 密码哈希 |
| `captcha_challenges` | `id`, `code_hash`, `expires_at`, `consumed_at` | 5 分钟有效、一次性 |
| `knowledge_bases` | `id`, `name`, `description`, `default_chunk_size`, `default_chunk_overlap`, `retrieval_mode`, `embedding_model`, `embedding_dim`, `created_by` | 管理员创建 |
| `documents` | `id`, `kb_id`, `filename`, `stored_path`, `file_type`, `size_bytes`, `sha256`, `chunk_size`, `chunk_overlap`, `status`, `progress`, `chunk_count`, `error_message` | `(kb_id, sha256)` 唯一 |
| `document_chunks` | `id`, `kb_id`, `document_id`, `chunk_index`, `content`, `char_start`, `char_end`, `page_no`, `metadata` | `(document_id, chunk_index)` 唯一 |
| `chat_sessions` | `id`, `user_id`, `title`, `settings` JSON | `settings` 存 kb_ids、温度、Top P、max_tokens、历史轮数 |
| `chat_messages` | `id`, `session_id`, `role`, `content`, `citations` JSON, `model`, `params` JSON, `status`, `error_message` | 状态 `streaming/ok/error/aborted` |

- InnoDB、`utf8mb4`；时间存 UTC。
- 文档级切块参数在上传时快照；知识库检索模式在查询时生效。
- 删除知识库/文档使用数据库级联，并在 Milvus 按 `kb_id` / `document_id` 删除。

## 4. Milvus 模型

单集合 `kb_chunks`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `chunk_id` | VARCHAR(64) 主键 | 文档块 ID |
| `kb_id` | VARCHAR(64) | 知识库过滤 |
| `document_id` | VARCHAR(64) | 文档过滤 |
| `chunk_index` | INT64 | 文档内顺序 |
| `page_no` | INT64 | 页码 / 幻灯片号，未知为 0 |
| `created_at` | INT64 | Unix 时间戳 |
| `content` | VARCHAR(8192) | 原文；启用中文 analyzer |
| `embedding` | FLOAT_VECTOR(1024) | bge-m3 稠密向量 |
| `sparse` | SPARSE_FLOAT_VECTOR | BM25 Function 输出 |

索引：

- `embedding`：`AUTOINDEX` + `COSINE`
- `sparse`：`AUTOINDEX` + `BM25`
- BM25 Function：`content -> sparse`
- Analyzer：`{"type": "chinese"}`（Milvus 内置中文分词）

检索：

- 稠密：`client.search(..., anns_field="embedding", metric_type="COSINE", filter=kb_id in [...])`
- 混合：`AnnSearchRequest` 稠密 + BM25，`RRFRanker(60)`
- 混合失败时降级稠密并记录日志。

## 5. 一致性

- **MySQL 是事实源**，Milvus 是派生索引。
- 入库：先写 MySQL 块，再写 Milvus；失败标记文档 `failed` 并清理向量。
- 编辑块：先 upsert Milvus（不阻塞 flush），再更新 MySQL；后台线程 flush。
- 删除：先尽力删 Milvus，再删 MySQL；失败记录日志，可用 `scripts/reindex.py --kb-id` 重建。
- 服务重启：把遗留 `parsing/chunking/embedding/indexing` 文档标记为 `failed`，提示重新解析。

## 6. 配置、日志与安全

### 配置

`.env` + `pydantic-settings`：

- 应用：`APP_ENV`、`APP_TITLE`、`LOG_LEVEL`、`LOG_DIR`
- 安全：`JWT_SECRET`、`JWT_EXPIRE_MINUTES`、`ADMIN_USERNAME`、`ADMIN_PASSWORD`
- MySQL：`DATABASE_URL`、`AUTO_CREATE_TABLES`
- Milvus：`MILVUS_URI`、`MILVUS_TOKEN`、`MILVUS_COLLECTION`
- bge-m3：`EMBEDDING_PROVIDER`、`EMBEDDING_MODEL`、`EMBEDDING_DEVICE`、`EMBEDDING_DIM`、`EMBEDDING_BATCH_SIZE`、`EMBEDDING_MAX_LENGTH`、`EMBEDDING_CACHE_DIR`、`EMBEDDING_PRELOAD`
- DeepSeek：`LLM_PROVIDER`、`DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`、`DEEPSEEK_THINKING`
- 检索：`TOP_K`、`DEFAULT_TEMPERATURE`、`DEFAULT_TOP_P`、`DEFAULT_MAX_TOKENS`、`DEFAULT_HISTORY_ROUNDS`

### 日志

- 控制台 + `RotatingFileHandler(logs/app.log, 10MB × 5)`。
- 请求中间件生成 `X-Request-ID`，日志带 request_id、方法、路径、状态、耗时。
- 入库记录文档、阶段、块数；LLM 记录模型、耗时；不记录 Key。

### 安全

- 密码 Argon2；JWT HS256；角色每次查库校验。
- 验证码 5 分钟有效、一次性、错误也消费。
- 上传限制扩展名/大小，UUID 存储，清洗文件名。
- 前端 Markdown 经 DOMPurify 消毒；Prompt 明确参考资料只是数据。
- `.env`、上传文件、模型缓存、日志不进 git。
